# Phase 4B — Interaction & Motion Audit

**Status:** Audit and proposal only. No source, token, copy, or layout was changed.
**Baseline:** `main` @ `3fe338f` (Phase 4A committed and pushed).
**Method:** Read CLAUDE.md, `Docs/PHASE4A_VISUAL_SYSTEM_AUDIT.md`, and every frontend file that animates, transitions, observes the viewport, or responds to input (list in Appendix A). Claims marked **(verified)** were checked against source or the production CSS build; claims marked **(inferred)** are reasoned from the code and need a browser or assistive-technology check during implementation. I did not run screen readers, and screenshots were unreliable in this environment, so nothing here is based on watching the animations play.

> **Scope guard.** 4A (visual system) is closed. 4C (illustration) and 4D (copy) are out of scope. The Phase 1 hero ("Gathering Point" + "Absorbed Facet") and its `hero-enter` entrance are locked and not touched by anything below.

### A. Foundations

#### A-1. Motion tokens and a reduced-motion policy

|                       |                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Current**           | Literals everywhere (§1); no global reduced-motion rule; three detection methods.                                                                                                                                                                                                                                                                 |

Every later change would otherwise repeat the problem.                                                                                                                                                                                                                                                                           |
| **Proposed**          | Define the tokens in §5 once in `@theme` / `:root`. Add one `@media (prefers-reduced-motion: reduce)` block that disables transform-based hover/press/entrance motion and animations, with a short list of exemptions (spinners). Add one `usePrefersReducedMotion()` hook (via `useSyncExternalStore`) to replace the ad-hoc `matchMedia` calls. |
| **Trigger**           | Passive                                                                                                                                                                                                                                                                                                                                           |
| **Motion properties** | n/a (policy). ## 6. Interaction principles

1. **Motion confirms an action or reveals a relationship.** If removing it would lose nothing, remove it.
2. **Respond first, decorate never.** Hover and press feedback starts immediately and is at most 200ms; nothing delays an action.
3. **Small and quiet.** Translate ≤ 12px, scale 0.97 to 1.03, one lift distance for the whole site.
4. **Transform and opacity only.** The two documented layout exceptions are `grid-template-rows` for FAQ and the mobile menu.
5. **No new ambient motion.** The hero remains the only continuous animation. Loops are allowed only while an operation is pending (skeleton, spinner) and must stop when it ends.
6. **One curve family, four durations.** New components pick from the tokens; literals are a review flag.
7. **Hierarchy through restraint.** Reveal lead blocks, not everything. Stagger at most three steps.
8. **Exit faster than enter.** Closes and exits are shorter and use the sharper easing.
9. **Hover is a bonus.** Every hover effect is gated to hover-capable devices and every state is also reachable by keyboard and touch.
10. **Reduced motion means less movement, not less meaning.** State, focus, and error communication are unaffected.
11. **Never trap or delay focus** with an animation.
12. **Prefer CSS over JS** (native `<dialog>` transitions, `inert`, `@starting-style`); JS only where state requires it.

## Appendix D. Risks

- **Screen-reader behaviour is inferred, not tested** (FAQ `inert`, live-region policy, counter accessible text). Needs a real NVDA/VoiceOver pass.
- **Native `<dialog>` transitions** (`@starting-style`, `allow-discrete`) require recent browsers; unsupported ones fall back to instant, which is acceptable but means not every visitor sees the same thing.
- **A global reduced-motion block can mask functional transitions** if any component later relies on `transitionend`; today none do (verified), but the rule belongs in the contribution notes.
- **`inert` and the mobile menu** change focus order when closed; keyboard regression testing required.
- **Testimonials has the most logic** of any component here; the timer fix and autoplay changes need tests, not just manual checks.
- **Reveal reduction changes the page's feel** (N-1). It is the most subjective item; it should be reviewed in the browser, not approved from this document.
- **Counter jitter fix** may need a font check (N-7b) or a small layout tweak (N-7a) inside the 4A stat layout.
- **Scroll padding** assumes a 72px header; if the header height changes, the offset must change with it.
